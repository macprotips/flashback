# Review of the September 11–12 changes

Reviewed the nine commits after `657d139` through `df1ef6e`, covering Java ME,
device descriptors, library layout, documentation, and release packaging.

The review found and fixed these issues:

| Area | Finding and correction |
| --- | --- |
| Java ME access restrictions | Mobile games bypassed the desktop Java policy. Both now use the same restricted host; game code can use its assets and saves while external files, networking, process execution, native loading, and policy replacement remain blocked. |
| Display and device profiles | The player read the wrong argument positions and wrote unused display-setting keys. Descriptor defaults now initialize the actual settings, and later choices made in the player survive reopening. |
| Phone buttons | Nokia selected Sagem's reversed softkeys; Siemens selected Sharp. The mappings now match the pinned player's definitions. |
| File and resource paths | Phone text encoding was incorrectly applied to file URLs. JARs, companion JADs, and resources now retain spaces, plus signs, percent signs, fragments, and accented characters. Both ordinary and fallback resource lookup use escaped URLs. |
| Startup and shutdown | A failed MIDlet could announce readiness, and the mobile player lacked the desktop host's parent watcher. Readiness now follows successful startup; failures propagate and closing the parent pipe stops the child. Invalid display descriptors and missing MIDlet classes are rejected. |
| Library responsiveness | JAR inspection blocked the main UI thread. It now runs in the background, with cancellation checked before launch. Duplicate configuration probing was removed. |
| Library presentation | Filter counts now describe the visible games, placeholders remain readable in light mode, and an older import completion cannot erase newer progress. Dialogs retain a parent window when focus changes. Geometry checks were updated for the revised card sizes. |
| Documentation and packaging | The release allowlist omitted the new user guide. Packaging now includes it beside the app and in the source archive. The guide explains companion JAD imports, saved settings, and the actual keyboard bindings. Source notices describe the FreeJ2ME changes. |

Validation on this Apple Silicon Mac:

- Universal ARM64/x86_64 build and local code-signature verification passed.
- Import, artwork, website recovery/routing, ZIP integrity, and catalog checks passed.
- A real authored MIDlet verified display settings, actual softkey codes, JAD and
  escaped resource loading, persistent records, changed device preferences,
  restricted permissions, failed startup, and parent shutdown. These checks now
  run during the build.
- Bounce Tales 2.0.3 and Wiz 3 passed the native import/launch checks, including
  duplicate-process prevention, recent history, and cleanup.
- Library geometry and interactions passed at five widths from 800 to 1440
  points in light and dark mode. Separate native dialog, cancellation, Help,
  About, and player-state checks passed; native screenshots were inspected.
- HTML playback verified assets, keyboard input, offline requests, restart,
  and saved storage. Missile Command and Free Running passed their recorded
  Shockwave opening-gameplay conditions.
- The Director patch reproduced the pinned source. Its runtime hash still
  matches the existing compatibility report; all 1,198 FreeJ2ME source hashes
  match the updated source manifest.

The workspace `Flashback.app` contains these fixes and is locally signed.
The existing distribution ZIP has not been rebuilt or published. These checks
do not establish whole-game compatibility, physical Intel behavior, or behavior
on older macOS versions; Shockwave remains experimental.

## 1.11.0 compatibility continuation

The follow-up work adds bounded support for embedded Flash projector movies,
local Java applets and JNLP descriptors, DOS games, and ScummVM-detected classic
Director games. Native engines run under `NativeHost` and `Native.policy`, which
limit them to the imported source and a private writable game directory, deny
network and process creation, and tie their lifetime to Flashback.

The release audit found and corrected three late issues. Applet JARs can now use
a valid parent-relative path from their declared codebase. DOSBox configuration
uses the current 0.83 `window_size` setting and defaults instead of deprecated
cycle settings. The build removes DOSBox's bundled offline manual because it
contains third-party game screenshots, preserves the runtime's JIT entitlement,
and runs the native sandbox and authored DOS checks as build gates. The release
signing script signs changed nested code from the inside out.

Validation on this Mac includes a universal 1.11.0 build, deep local signature
verification, all native sandbox denials, and two executions of an authored DOS
program with private-save preservation. Happyland Adventures reached its real
title menu through the final app; Flashback's self-check then passed import,
visible-window readiness, duplicate prevention, history, cleanup, and library
rendering. The original Happyland folder was unchanged, while its private copy
created the expected DOS extender swap file. An official ScummVM Director demo
was detected and launched; its log records a Director v300 game start.
The complete Shockwave compatibility corpus was rerun against this build:
19 of 20 titles passed their recorded opening-gameplay conditions, and Backlot
remained the documented limited case that opens without an asserted interaction.
No corpus case failed.

Discover now presents a static three-card **Top games this week** preview and an
explicit control to expand all 24 recommendations. The selection changes by one
24-game cohort each UTC week and remains stable during a session. Searches and
format filters are unchanged, duplicates are removed, and the focused check
proves that every curated identifier eventually reaches a weekly set. The review
JSON now accounts for all 141 identifiers compiled into the app.

The Discover screen also offers provider cards for Internet Archive, DOS Games
Archive, DOSGames.com, itch.io, GOG, and ScummVM, followed by eight link-only game
recommendations. The source review is recorded in `DISCOVER-SOURCES.md`.
Flashback does not download those links automatically or bundle their files.
Happyland Adventures is the only external recommendation labelled Tested; the
other cards make no compatibility claim. The rebuilt native catalog UI check
passed after exercising expansion and inspecting normal, dark, and compact
screenshots.

Release packaging remains intentionally blocked. DOSBox's full source closure,
including its vcpkg and nested FreeDOS inputs, now verifies, but the official
ScummVM Mac executable lacks exact source, patches, and build recipes for all
statically linked libraries. This Mac also has no Developer ID Application
identity or saved notarization profile. No release ZIP was created or published.

The DOS archive matrix exposed one additional importer defect: Java's standard
ZIP reader rejected older archives compressed with Implode method 6. The importer
now uses checksum-pinned Apache Commons Compress 1.28.0 with its required Commons
IO and Commons Lang libraries while retaining the existing entry, size, time,
path, collision, symlink, and CRC limits. The final packaged helper extracted a
real Lemmings demo archive and found its executable and data files. The optional
Classic Windows prototype is now excluded from ordinary builds and hidden from
the menu; release packaging rejects it if a development build contains it.
