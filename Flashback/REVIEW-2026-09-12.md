# Review of the September 11–12 changes

Reviewed the nine commits after `657d139` through `df1ef6e`, covering Java ME,
device descriptors, library layout, documentation, and release packaging.
The deliberate removal of the downloaded collection remains intact.

The review found and fixed these issues:

| Area | Finding and correction |
| --- | --- |
| Java ME access restrictions | Mobile games bypassed the desktop Java policy. Both now use the same restricted host; game code can use its assets and saves while external files, networking, process execution, native loading, and policy replacement remain blocked. |
| Display and device profiles | The player read the wrong argument positions and wrote unused display-setting keys. Descriptor defaults now initialize the actual settings, and later choices made in the player survive reopening. |
| Phone buttons | Nokia selected Sagem's reversed softkeys; Siemens selected Sharp. The mappings now match the pinned player's definitions. |
| File and resource paths | Phone text encoding was incorrectly applied to file URLs. JARs, companion JADs, and resources now retain spaces, plus signs, percent signs, fragments, and accented characters. Both ordinary and fallback resource lookup use escaped URLs. |
| Startup and shutdown | A failed MIDlet could announce readiness, and the mobile player lacked the desktop host's parent watcher. Readiness now follows successful startup; failures propagate and closing the parent pipe stops the child. Invalid display descriptors and missing MIDlet classes are rejected. |
| Library responsiveness | JAR inspection blocked the main UI thread. It now runs in the background, with cancellation checked before launch. Duplicate configuration probing was removed. |
| Library presentation | Filter counts now describe the visible games, placeholders remain readable in light mode, and an older import completion cannot erase newer progress. Dialogs retain a parent window when focus changes. Geometry checks were updated for the revised card sizes. |
| Documentation and packaging | The release allowlist omitted the new user guide. Packaging now includes it beside the app and in the source archive. The guide explains companion JAD imports, saved settings, and the actual keyboard bindings. Source notices describe the FreeJ2ME changes. |

Validation on this Apple Silicon Mac:

- Universal ARM64/x86_64 build and local code-signature verification passed.
- Import, artwork, website recovery/routing, ZIP integrity, and catalog checks passed.
- A real authored MIDlet verified display settings, actual softkey codes, JAD and
  escaped resource loading, persistent records, changed device preferences,
  restricted permissions, failed startup, and parent shutdown. These checks now
  run during the build.
- Bounce Tales 2.0.3 and Wiz 3 passed the native import/launch checks, including
  duplicate-process prevention, recent history, and cleanup.
- Library geometry and interactions passed at five widths from 800 to 1440
  points in light and dark mode. Separate native dialog, cancellation, Help,
  About, and player-state checks passed; native screenshots were inspected.
- HTML playback verified assets, keyboard input, offline requests, restart,
  and saved storage. Missile Command and Free Running passed their recorded
  Shockwave opening-gameplay conditions.
- The Director patch reproduced the pinned source. Its runtime hash still
  matches the existing compatibility report; all 1,198 FreeJ2ME source hashes
  match the updated source manifest.

The workspace `Flashback.app` contains these fixes and is locally signed.
The existing distribution ZIP has not been rebuilt or published. These checks
do not establish whole-game compatibility, physical Intel behavior, or behavior
on older macOS versions; Shockwave remains experimental.
